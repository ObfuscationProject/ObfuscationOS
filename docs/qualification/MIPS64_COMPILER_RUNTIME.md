# MIPS64 binary128 user compiler runtime

The retained N64 big-endian MIPS64r2 hard-float musl profile uses 16-byte IEEE binary128 `long double`. The installed mips64-elf GCC14.2.0 runtime omits its TF helpers. Even integer printf can pull them through musl vfprintf. The OS supplies a separately selected archive; the Kernel SDK and installed compiler are unchanged. All ten architecture profiles remain supported by their existing build recipes. This addition changes only the explicit MIPS64 application link.

`docs/plans/contracts/mips64-softfp.json` pins GCC14.3.0 archive bytes and43 selected source/license files. All25 soft-fp translation units and the MIPS sfp-machine header are unchanged upstream sources. The output has28 public helpers (including comparison aliases), no unresolved imports, N64 ELF64 big-endian MIPS64r2/PIC attributes,64-bit GPR/CPR1 and hard double FP ABI. The selected profile uses legacy MIPS NaNs. Its upstream implementation reads rounding mode and records IEEE exception flags through FCSR; enabled traps are not qualified by the fixture.

Build with `xmake mips64-softfp --archive=/absolute/gcc-14.3.0.tar.xz --toolchain=/absolute/mips64-elf --mode=debug --out=/absolute/new-build`. Release requires a separate matching-mode artifact. No network fetch or implicit search is performed. The manifest records sources, compiler/front-end/assembler tools, command logs, exact archive and all objects; it labels output built-not-executed. Upstream GPL, LGPL and Runtime Library Exception texts are retained with the source and installed license directory. The archive checksum is a source identity pin, not a verified upstream signature.

`tools/build_musl_probe.py` and `xmake musl-bootstrap-probe` accept `--softfp-build` together with `--softfp-manifest-sha256`. Both are required to enable the supplement, only for MIPS64, with matching mode and compiler bytes. The consumer rehashes the complete artifact inventory, checks the upstream source pin, every object ABI, exact archive member bytes and the complete GNU linker symbol index, and links the explicit archive inside the libc/libgcc group. A missing, wrong-mode, stale or incomplete artifact is rejected. Ordinary native programs and the other nine profiles keep their existing link paths.

The fixture `tests/musl/mips64_softfp.c` executes every exported helper and checks exact arithmetic patterns, signed zero, subnormals, halfway ties, all four rounding modes, sticky exception flags, quiet/signaling legacy NaNs, comparison aliases, float/double and32/64/128-bit integer conversions, strtold, snprintf and actual printf output. The Linux user-emulation reference must explicitly use `qemu-mips64 -cpu MIPS64R2-generic`; the default5KEf CPU does not supply the selected FCSR behavior and is not this release profile.

`tools/qualify_mips64_softfp.py` separately consumes an exact exported SDK25 and matching musl and runtime manifests, builds a fresh SDK-only OS, installs the ELF on a scratch ext4 root and executes it twice. It checks complete per-command printf/success records, a native pipeline before and after, allocation/retirement accounting and offline filesystem diagnostics. Hosted artifact/parser models, Linux user emulation and full-system ObfuscationOS execution are separate evidence categories. None proves complete libc/libm, pthread, floating-point context concurrency, SMP, physical support or M3 completion.
